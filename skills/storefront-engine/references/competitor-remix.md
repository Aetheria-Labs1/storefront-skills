# Reference-led adaptation

A competitor reference provides observable structure and design hypotheses,
not merchant-owned copy, product data, proof or imagery. Scope the requested
adaptation before changing the current page.

## Workflow

1. Capture the supplied URL at relevant widths. Record the URL, date,
   viewport and observable hierarchy; distinguish inaccessible sections from
   content actually inspected.
2. Separate page jobs from implementation details. Map those jobs to the
   selected contract in `references/page-types/_index.md` and note deliberate
   deviations instead of copying another default section order.
3. Use the current merchant's catalogue, claims, offer terms and eligible
   media. `references/workflows/_how-to-read.md` owns execution.
4. Resolve interactive behavior from live schemas, not the reference site's
   DOM names. Author editable source through
   `references/authoring/source-authoring.md`.
5. Compare the hosted draft with the intended reference qualities using
   `references/qa-recipe.md`: hierarchy, product clarity, spacing and mobile
   decisions. Record intentional differences and unverified interactions.

Do not claim pixel or behavior parity without inspection. Do not copy assets
or claims merely because they are visible on a public page. Publish only
through the explicit publication workflow.
