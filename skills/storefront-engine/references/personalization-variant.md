# Persona-specific variants

Use a variant when a confirmed audience need warrants different messaging,
imagery or section emphasis. Read `references/ab-testing.md` for source-based
duplication, credit approval, variant review and experiment lifecycle.

## Define the difference

Read `lexsis_campaigns.personas`, the owned base page's source/edit context
and relevant analytics. Confirm the target audience, decision friction,
protected elements, primary metric and exact changes. Treat persona labels
as hypotheses, not proof about individual visitors.

Keep brand identity and true product facts stable. Select real, rights-cleared
assets through `references/workflows/section-asset-workflow.md`; an audience
label does not authorize synthetic people, customer proof or paid generation.
Keep all claims and reviews tied to the same proof/offer requirements as the
base page.

## Create and verify

Prepare each challenger as a separate source value, compile it, and apply it
to an approved duplicate with version protection. Do not create local files
or use `page_variation` as a shortcut around reviewed experiment setup.
Verify each hosted variant's source, integrity, mobile layout, commerce and
approved differences. Keep its page id, version, preview URL and QA evidence.

## Routing boundary

Discover the current experiment schema before recording weights, metrics or
targeting. Do not invent persona-targeting fields or promise automatic
individual personalization. Starting traffic or publishing variants requires
separate explicit approval and a supported live operation.
